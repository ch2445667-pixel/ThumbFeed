Replace scraped view text with real view counts and publish dates

The importer stored whatever text it could scrape off the channel grid:
"423K views views", "2 million views", "2.2 thousand views". The duplicated
suffix and the spelled-out numbers came from the extractor concatenating an
accessibility label with a fallback. Upload dates were worse -- created_at was
the row's insert timestamp, so every tile claimed to be uploaded on the day the
import ran, and 27 rows carried a relative note like "Published: 6mo ago".

scripts/fetch-stats.mjs walks every thumb-yt-* row and asks InnerTube for the
exact viewCount and ISO publishDate. Views are stored as K below a million and
M above ("423K views", "1.2M views", "18M views"); counts under a thousand
stay exact rather than rounding a real number to "1K". created_at becomes the
video's real publish date, so formatTimeAgo renders a true age, and
breakdown_notes gains a "Published: YYYY-MM-DD" marker.

YouTube answers LOGIN_REQUIRED once a burst of player calls goes through, which
cost 353 rows on the first pass. The script now falls back to the public watch
page for a single rejected call, drops concurrency to 2, and pauses as failures
accumulate. Re-running it resumes: only rows without an exact-looking value are
fetched. 2149 of 2150 rows now carry real figures.

The one holdout, thumb-yt-v7O8ZUgGRCI, is UNPLAYABLE on every client including
the watch page. Its publish date was recoverable from the page and is recorded;
the view count is left null rather than guessed.

Verified in the browser: 14K / 401K / 761K / 3.1M / 5.4M views with 10mo, 2mo,
5y, 1y, 1mo ages, no broken images, grid still on small WebP variants.
